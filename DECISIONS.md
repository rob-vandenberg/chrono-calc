# DECISIONS.md

Every design decision as it stands now, by topic, short. Every decision here was approved through the owner's Proceed. New decisions get the next free number.

## The product

- **D-008** Chrono Calc does everything the Windows 7 Calculator does: the same results, views, side panels, keys, shortcuts, menus and layout (AGENTS.md §0). (2026-10-30)
- **D-005** Our own look, very very close to the old calculator: same layout, proportions, colours and feel; every image, icon and button drawing is our own; nothing of Microsoft's artwork is copied. (2026-10-30)

## Technology

- **D-001** C++20 with Qt 6 Widgets, built with CMake. Reason: the open-source engine of the Windows calculator is C++ and can be used as it is; Qt is native on KDE and works on GNOME and Windows; one small program, quick to start, simple to package. Python with PySide6 was rejected (rewrite of the engine or two languages, slower start, heavier packages). (2026-10-30)
- **D-006** The licence is AGPL-3.0-or-later, the same as Chrono Mail. The MIT engine is compatible. (2026-10-30)

## The engine

- **D-002** The maths is the engine of microsoft/calculator (`CalcManager`, `RatPack`, MIT, released 2019), copied unchanged into `third_party/calculator/`, from commit `79e1ac5` (2026-10-20); a reference clone of the whole repository is in `/home/rob/c++/calculator`. Microsoft never released the Windows 7 Calculator's own code; the Windows 10 engine descends from it. (2026-10-30)

- **D-010** Only the engine core is imported: `CEngine`, `Ratpack`, `CalculatorManager`, `CalculatorHistory` and their headers; its `pch.h` is replaced by our own in `core`. `UnitConverter` is left out (it needs the Windows-only PPL tasks, and its unit lists are Windows 10's). Unit conversion, Date calculation, the Statistics view and the Worksheets are our own code in `core`, because Windows 10 has none of them in C++; every result they give is computed with the engine's exact fractions (`Rational`), never with floating-point maths. Microsoft's C++ engine tests are ported to Qt Test to prove the engine works the same on Linux. (2026-10-30)

## Build and checks

- **D-011** The layers are `third_party` <- `core` <- `ui` <- `app`: a layer includes only from the layers below it; `core` is plain C++ without Qt. `tests/test_layers.cpp` enforces it (OR-13) by reading every `#include` in `src/`. (2026-10-30)
- **D-012** Two builds, GCC and Clang (`CMakePresets.json`: `gcc`, `clang`, Ninja, `build/gcc`, `build/clang`). clang-tidy runs during every build of our own code with the families bugprone, clang-analyzer, cppcoreguidelines, modernize, performance, readability and misc, every finding an error; off: trailing return types, magic numbers, identifier length, owning-memory (Qt parents own their children); `misc-include-cleaner` skips Qt's own headers. Each reason is in `.clang-tidy`. clang-tidy is the developer's gate on this computer; the release builds in containers (D-009) run without it (`-DCHRONO_CALC_CLANG_TIDY=OFF`). (2026-10-30)

- **D-014** The engine import (task 0.2), described in `third_party/calculator/SOURCE.md`: 53 files of `src/CalcManager` copied unchanged, with Microsoft's `LICENSE`; left out are `pch.h` (Windows-only headers), `UnitConverter` (D-010), `CalculatorVector.h` (unused) and the Windows build files. Two measures of ours, both outside Microsoft's files: `third_party/calculator/shim/pch.h` (the same standard headers without the Windows ones; it lives in `third_party`, not `core`, because a lower layer may not include a higher one, D-011), and `<cmath>` given to `Ratpack/support.cpp` through a compiler option. The engine is the library `chrono_calc_engine`, built without warnings-as-errors and without clang-tidy; its headers are system includes for our code. Microsoft's engine tests (71) are ported to Qt Test in `tests/engine/`, every check and expected value unchanged, with the en-US engine texts of `CEngineStrings.resw` in `engine_resource_provider.cpp`. The layer check also covers `third_party`: no Qt, `core`, `ui` or `app`. (2026-10-30)

- **D-015** The engine wrapper (task 0.3): `core/calculator` holds one `CalculatorManager` in Standard mode and keeps what it reports (number, expression line, error, memory) as plain values; the expression line is the engine's tokens joined as they come (they carry their own spacing). Commands go in by id through the registry `core/commands` (`digit.0`-`digit.9`, `decimal`, `add`, `subtract`, `multiply`, `divide`, `equals`, `clear`, `clear_entry`, `backspace`, `negate`, `sqrt`, `percent`, `reciprocal`, `memory.clear/recall/store/add/subtract`, `view.standard`). One memory, as in Windows 7 (since D-017 the engine's own register). `core/enginetexts` gives a text for every text number the engine can look up, because the engine's `GetString(int)` stores a key pointing to a temporary string for a number without a text: the 108 en-US texts of `CEngineStrings.resw` plus 41 of ours (digits, memory names, five rare error messages), to be checked against Windows 7 in task 1.5. The number separators are en-US until Digit grouping (M5). (2026-10-30)
- **D-016** `chrono-calc-cli` (task 0.4): the calculator without a screen. Each argument is a command id or a run of typed characters (`core/keys`: digits, `.` `,` `+` `-` `*` `/` `=` Enter `@` `%` `r`, as in Windows 7); it prints the display, the expression line, error and memory. Used by tests and for quick checks. (2026-10-30)

- **D-017** The wrapper drives the engine (`CCalcEngine`) directly, without Windows 10's `CalculatorManager` (task 1.5): the engine's one memory register is Windows 7's memory (MC, MR, MS, M+, M-; "M" shows while it is not 0); it starts at 0 because a recall from a never-set register would read nothing, and every read puts the value back (`PersistedMemObject()` moves it out). Windows 7 percent: y% is y * x/100 after every operator; the engine does so after + and -, but after * and / it takes y/100 (Windows 10), so there the wrapper reads x right after the operator and enters y * (x/100) with the engine's `Rational`, the engine's own formula. The expression line is built as Windows 7 shows it: the finished chain with `+ - * /` (`2 + 3 *`), then the current value's own part from the engine (`sqrt(9)`, `reciproc(5)`, the percent value); empty after `=`, except after an error (`1 /`); an operator right after one replaces it. The engine's `m_decimalSeparator` has no start value (CalcEngine.h:166), so after construction the wrapper reports another separator once and then the real one, which makes `SettingsChanged()` set the input's decimal symbol in every case (found by the reference test: "0,1" read as an overflow). Separators come from the caller (`Separators`). All 20 Windows 7 reference results pass (`tests/test_reference_standard.cpp`). (2026-10-30)

- **D-018** The Standard view's window (tasks 1.1 to 1.4): the measures of the Windows 7 reference (client 264 x 331, display frame, 28 buttons) live in `core/standardlayout`, the menus in `core/menus` (every Windows 7 item present; an item without a command is greyed and shows its shortcut without taking the key; only View > Standard and Basic are built; choosing either again changes nothing, as in Windows 7; the access keys are Windows 7's), the keys in `core/keys` (characters; Escape = C, Delete = CE, Backspace, Enter = equals, F9 = plus/minus; Ctrl+L MC, Ctrl+R MR, Ctrl+M MS, Ctrl+P M+, Ctrl+Q M-). The window draws everything itself in our own drawing (`ui/calcbutton`: a light face with a blue-grey edge, a golden glow under the mouse, orange when pressed; `ui/displaypanel`: a white-to-blue frame, the expression line showing its end when long, the mark M with a hover text, the number drawn smaller when long) with Qt's Fusion style and only the colours of `core/colours.h` (`ui/look`), so the desktop theme changes nothing. The colours and figure sizes are measured in Windows 7 (`tests/reference/windows7-standard.md` part G); its fonts are not on Linux, so the computer's own fonts are sized by the height of their digits (`ui/fonts`: the display in the fixed-width font, as Windows 7). Buttons never take the keyboard focus: every key goes to the calculator, and a typed key shows its button pressed for 100 ms, in the drawing only, so a click the mouse is making is never disturbed. The decimal button shows the regional separator. The window has a fixed size and opens where it was closed (`QSettings`, `~/.config/chrono-calc/chrono-calc.conf`), unless that place is on no screen; on Wayland the desktop places windows itself. (2026-10-30)
- **D-019** The rest of task 1.5, checked on the Windows 7 Calculator (reference lines 21 to 36): the keys of D-018 are Windows 7's (the reciprocal is the R key); MR on an empty memory shows 0; the memory at 0 shows no M (storing 0, or M- down to 0); a percent right after = takes the result as its base (2*3=5% is 0,3 and the expression line shows 0,3), done in the wrapper with the engine's own formula and `Rational`, like D-017's percent; View > Standard and Basic chosen again keep the number and the expression line. All 36 reference lines pass. (2026-10-30)

- **D-020** The Scientific view (M2), measured on the Windows 7 Calculator (`tests/reference/windows7-scientific.md`): the wrapper holds two engines, as Windows 10 does: Standard (left to right, 16 digits) and Scientific (precedence, 32 digits); the one memory moves with a view change. A view change clears the number and the expression line and keeps the memory; Scientific starts in Degrees with Inv and F-E off. Inv is the wrapper's: a function with an inverse form (sin, cos, tan, sinh, cosh, tanh, ln, Int, dms, pi) gets the engine's own Inv and Inv turns off; on the others it stays on and does nothing; C and CE turn it off. F-E is the engine's: C turns it off, CE keeps it. % is greyed and does nothing in Scientific. The expression line is the engine's own tokens with Windows 7's names (sind, asind, sinr, sing, powe, powten, `*`, `/` in `core/enginetexts`) and tight brackets ("(2 +"); empty after =, kept after an error. Numbers are not grouped in any view (View > Digit grouping starts off in Windows 7, M5); this also corrects the Standard view, which showed 1,234. The keys are Windows 7's per view (`core/keys`: letters only without Shift; F3 to F5; Ctrl+Y/G/B/S/O/T). The layouts of both views live in `core/layout` with each button's face (digit, function, memory flat, toggle amber when on; this also gives Standard its function and memory faces) and label size; the window rebuilds the buttons and takes the view's size on a view change, and opens in the view it was closed in (`QSettings` `window/view`). Our own drawing for the angle units and the bracket counter (`ui/scientificparts`). While an error shows, only C and CE reach the engine, in both views (Windows 7: every other key and button is ignored, MS and MC too): the switches and the expression line stay as they are. Windows 7's fault of keeping F-E on inside after C during an error is not copied (a box that says off while numbers show 5,e+0 misleads). All 45 Windows 7 Scientific results and the error lines pass (`tests/test_reference_scientific.cpp`). (2026-10-30)

- **D-021** The Programmer view (M3), measured on the Windows 7 Calculator (`tests/reference/windows7-programmer.md`): a third engine in the engine's integer mode with precedence and 64 bits, as Windows 10 has; it keeps its base and word size over a view change (Windows 7 does), the number is cleared and the memory kept. The wrapper tracks the base and word size for the choices and for what each base allows (`Calculator::isAvailable`: never the decimal point, √, % and 1/x; A-F only in Hex, 8 and 9 not in Oct, 2-9 not in Bin); a command not allowed does nothing, so typed keys behave like the greyed buttons. The expression line is empty in Programmer. The engine always groups Hex, Oct and Bin with spaces (Windows 10's fixed choice, `GroupDigitsPerRadix`); the wrapper shows those numbers whole, as Windows 7 does with Digit grouping off. The bit display shows the engine's own binary text (`GetCurrentResultForRadix`), only the bits of the word size; a click on a bit runs the engine's bit command (`bit.0` to `bit.63`). The choices of every view (angle units, bases, word sizes) are one kind of control (`ui/viewparts`, `core/layout` `ChoiceSpec`); A-F have a flat face. Keys per Windows 7: & | ^ ~ < > % ( ), a-f, j k, F5-F8 bases, F12 F2 F3 F4 word sizes. The number library's radix and precision are shared by the three engines, so the engine of a view sets its own again on every view change, as Windows 10 does (found in review: wrong results after a view change). The memory keeps its value over a view change as in Windows 7 (part F), except Windows 7's fault with -1,5 in Programmer, which is not copied. Letter keys are read as keys, as Windows 7 does: without Shift they work with Caps Lock too; A-F also with Shift. All 30 Windows 7 Programmer results and the behaviours of parts B and F pass (`tests/test_reference_programmer.cpp`). (2026-10-30)

- **D-022** Keyboards without Latin letters (Russian, Greek, Hebrew, Thai, Arabic), measured in Windows 7 (`tests/reference/windows7-programmer.md` part F lines 5 and 6): Windows 7 binds its letter shortcuts to the key, and on such a layout a letter key is the US letter of its place; that letter's command in the view wins, and only where the view has none does the typed character count (Greek Q types ; and is x² in Scientific, nothing in Standard; Hebrew Q types / and divides in Standard, is x² in Scientific). Chrono Calc does the same (`MainWindow` `placeKeyOf`): the place is the PC scan code (`core/keys` `latinLetterAtScanCode`; Qt on Linux gives the XKB key code, the scan code plus 8; on Windows the virtual key itself). A key whose XKB symbol is a letter of another script is from such a layout; this also covers Ctrl with two layouts, where Qt gives the other layout's Latin letter (German and Russian: Ctrl+я comes as Y, Windows 7 reads Z). A sign on a letter's place is looked up in the layouts in use, because Qt does not say which layout typed it (`ui/keyboardlayouts`: on Wayland, also under XWayland, the desktop's keyboard description over a connection of our own; on X11 the names in `_XKB_RULES_NAMES`; elsewhere XKB's defaults; read again when a key is not found, at most once every 2 seconds, so a layout added later counts); a layout is not Latin when most of its letter keys type letters of another script. Latin layouts (AZERTY, QWERTZ, Dvorak) are read by their own letters and signs as before. Builds need xkbcommon, xcb and wayland-client (Qt needs them too). Not handled: Greek or Cyrillic on a higher level of a Latin layout (Neo) gives the letter of the key's place; remote X servers whose key codes are not the scan code plus 8; an X11 keyboard changed by hand (xkbcomp, xmodmap) without new names. Not measured: Latin letters outside A to Z on a letter's place (the Turkish ı), which are read as typed. (2026-10-30)

- **D-023** The Statistics view (M4), measured on the Windows 7 Calculator (`tests/reference/windows7-statistics.md`): a fourth engine without operators and with Standard's 16 digits (Windows 7's precision there); no expression line, no CE, no Inv, nothing greyed. The list is the wrapper's: exact values (`Rational`), each written by the engine as its display writes numbers (16 digits, F-E, the regional separator), the newest selected after Add; Add puts the number shown (also a statistic's result, also 0 right after Add) and shows 0. The statistics are our own code in `core/statistics` on the engine's exact fractions with the engine's own square root (D-010): x̄, x̄² (mean of squares), Σx, Σx², σn = √(Σ(x-x̄)²/n), σn-1 = √(Σ(x-x̄)²/(n-1)); every statistic of an empty list and σn-1 of one value show Windows 7's "Enter data to calculate", an error of the wrapper during which only C and CAD work. C keeps the list, CAD clears it, the memory stays with both. A view change clears the number, keeps the list and turns F-E off. The list (`ui/statisticsparts`) takes the keyboard focus only from a click; then the arrows, Home, End, Page Up and Page Down move the selection and Delete removes the selected value (the next one moves into the selection); every other key goes to the calculator; Enter, Escape and a click on a calculator button give the focus back; the ▲ ▼ buttons move the selection and give the list the focus. Every list action is a command (`statistics.select.N` carries the item's index in its id; `statistics.select_previous`, `statistics.select_next`, `statistics.delete`); `chrono-calc-cli` prints the count, the list and the selected item in this view. A statistic the number library cannot compute shows the engine's own overflow error (no list Windows 7 accepts reaches it). Keys: Enter Add, A S T x̄ Σx σn, Ctrl+A/S/T x̄² Σx² σn-1, D CAD, X and E Exp, V F-E. Windows 7's fault of never removing the last value with Delete is not copied (only CAD could empty the list). The list is not kept after the calculator closes, as in Windows 7 (checked by the owner). All Windows 7 results and behaviours pass (`tests/test_reference_statistics.cpp`). (2026-10-30)

- **D-024** History, Digit grouping and Edit (M5), measured on the Windows 7 Calculator (`tests/reference/windows7-history.md`). History: one list per view (Standard, Scientific), kept by the wrapper from what the engine records (its own history holds only the last calculation), so that an entry can be edited in place; a Standard chain the engine records step by step ("2 + 3", "5 * 4") is one entry ("2 + 3 * 4"), as Windows 7 shows it; at most 1000 entries (Windows 7 kept all of 150). An entry is the expression only; choosing it (a click, Up/Page Up, Down/Page Down while History is shown, ▲ ▼) shows its result as the display wrote it (16 or 32 digits), not the exact value, as Windows 7 does (1/3 chosen, *3= gives 0,9999999999999999); an error shown is cleared first; a pending operator stays. View > History (Ctrl+H, a tick) makes Standard and Scientific 125 px taller with the list in the display (the Statistics list's look), greyed with its tick kept in Programmer and Statistics. Edit > History: Copy history, Edit (F2; Recalculate = while editing), Cancel edit, Clear (Ctrl+Shift+D, the list only). Edit reads the text with `core/historyedit` (numbers with the regional decimal symbol, the thousands symbol skipped, a sign before a number, "1,e+5"; + - * / ^ Mod yroot; brackets; the functions by the names the engine writes them with) and calculates it in an evaluation engine of the view (left to right or with precedence); a text that cannot be read or ends in an error keeps the box open; a view change applies the edit, Ctrl+H drops it; a calculator button click types its character into the box. Every engine skips writing its number when it equals what the last engine wrote (a cache all engines share, `scidisp.cpp` gldPrevious), so an evaluation engine ends with a clear, which makes the next engine write again (found while building: the chosen result did not show). Digit grouping (a tick): the engine's own grouping with the regional pattern, read from the locale ("3;0", India "3;2;0"; Programmer: Hex and Bin by four, Oct by three, with spaces), also the Statistics list; never the expression line or the history. Copy (Ctrl+C, Ctrl+Insert) copies the number as shown; Copy history and Copy dataset end each line with "\n", the Linux line end (Windows 7: "\r\n"). Paste (Ctrl+V, Shift+Insert; greyed without text on the clipboard) types the text as the view's keys (the rules of part F: the other decimal symbol and unknown characters skipped, a leading minus is the sign, "e+" skipped where the view has no Exp, a line end ends the number or is Add in Statistics, a minus at the start of a line is the sign (not measured: a pasted Copy dataset keeps its values), ":m :r :p :q :c" the memory, q is C in every view), at most 10000 characters; nothing while an error shows. Found in review: the engine's = closes open brackets in a loop that never ends when its precedence stack (25) is full and it refuses the ")"; the wrapper closes them one by one before = and = does nothing when one cannot be closed; an edit the engine cannot take (a bracket beyond its depth, an exponent of more than four digits, which it would cut short) is not taken. The Statistics view's Edit menu: Copy dataset, Edit (F2) of the selected value, Cancel edit, Clear (D, CAD). Remembered with the view and the position: History shown and Digit grouping (`window/history`, `window/digitGrouping`), as Windows 7 keeps ShowHistory and UseSep. Windows 7 faults not copied, because they hurt the user: Escape adds a pending function (9 sqrt) to the history while the C button does not (Escape is C here); a Statistics edit that is no number removes the value (the box stays open, a typing mistake never throws a value away); the Statistics Edit item disappears while editing and Programmer has no History submenu (both greyed instead: grey out, never hide). Not copied: the 150 ms slide of the window height (it changes at once; a window resized step by step is jerky on Linux desktops). The edit box is white with black text (Windows' own colours, not measured). (2026-10-30)

- **D-025** Unit conversion (M6), measured on the Windows 7 Calculator (`tests/reference/windows7-unitconversion.md`). The side panels are one family: `SidePanel` (Basic, Unit conversion, Date calculation, the four Worksheets) is the calculator's, chosen by `view.basic`, `view.unit_conversion` (and M7 and M8's own) with one dot in the View menu; the panel shows beside every view (never greyed), 454 px wide and 13 px right of the view (`core/layout` `sidePanelLayoutOf`: the height per view as measured, Scientific with History taken as Standard's), the window grows by it; a view change and Basic keep the panel's state; the panel shown is remembered (`window/sidePanel`, as Windows 7's UnitConv/DateTime/Templates), its choices are not (Windows 7 keeps none). `ui/sidepanels`: the frame (white, #889AAD edge) and our own drawing of the lists and boxes in the colours measured there; M7 and M8 build their panels from the same parts. Unit conversion: the 11 types and their units in Windows 7's order and spelling (`core/unitconversion`); each unit's size in the type's base unit as an exact number written out (Kelvin the base of temperature, with the offset of Celsius and Fahrenheit), converted with the engine's `Rational` only (D-010), pi from the engine for the radian; the To box is the engine's own writing of the number with 16 digits and the regional decimal symbol (`Rational::ToString`, "6,21371192237334e+16"), never grouped, worked at 32 digits in base 10 and the current view's constants set back after (the Programmer engine may be in Hex). `core/unitconverter`: the type, both units, the From text and the result; a type chosen sets both units to its first and empties both boxes; a unit chosen keeps From. The From box is its own, apart from the display (neither changes the other); it takes digits, the regional decimal symbol, + - and a small e as typed, at most 25 characters (a 26th is refused); a number is read as Windows 7 reads it (part G, the same as the Worksheets, D-027, but a minus is allowed): at most 16 digits, zeros before the whole part's first other digit not counted, "," "-" "+" alone are 0, "e5" is 1e+5, "1e" is 1, an exponent of at most four digits, otherwise the To box is empty; a From typed with an exponent gives a To written with one ("e5" Meter is "1,e+7" Centimeters; found in review, `writtenNumber` in `core/unitconversion` writes the mantissa itself because the engine's exponent form keeps fewer digits below 1). Commands: `unit.type.N`, `unit.from.N`, `unit.to.N` and `unit.input` (a text); `chrono-calc-cli` prints the panel. Keys: a list passes every key but Up, Down, F4 and Alt+Up/Down to the calculator, Enter and Escape give the calculator the focus; the From box keeps every key (F9, Enter, Escape do nothing); Tab order From, its unit, To, its unit, the calculator, the type list. Windows 7 faults not copied, because they give wrong results: the millimetre of mercury (133.3 Pa: 1 atmosphere showed 760,1275318829707, it is 760 by definition; we use 101325/760 Pa), the pound per square inch (6894.757 Pa; we use 0.45359237 * 9.80665 / 0.0254²), the electronvolt (CODATA 2002; we use the exact SI value 1.602176634e-19 J) and the foot-pound cut to 1.3558179483314 J (we use the exact 1.3558179483314004; the last digit of 1 BTU in foot-pounds differs); 1 radian in degrees, which Windows 7 shows as 57,29577951308233 (180/π is 57,295779513082320877: we show 57,29577951308232, found when the tests first ran). Kept as Windows 7 has them: Mach at 340.2933 m/s and the printer's pica 0.0042175176 m (no exact definition), the IT calorie 4.1868 J (exact). Not copied (found in review): the BTU 1055.056 J; the IT BTU is exactly 4.1868 J/g * 453.59237 g * 5/9 = 1055.05585262 J, which changes every Energy and Power cell of the BTU. Not copied: an invalid From holding the keyboard focus with "this value is not valid" (the To box is just empty). Not measured: a result with one digit before the exponent, which the engine writes "1,e+32" as the display does. (2026-10-30)

- **D-026** Date calculation (M7), measured on the Windows 7 Calculator (`tests/reference/windows7-datecalculation.md`), a side panel of D-025's family (`view.date_calculation`, Ctrl+E; the same frame beside every view; the mode list takes the keyboard focus when the panel is chosen). Two modes in a list, each keeping its own dates, numbers and results over a mode, view or panel change (`core/datecalculator`); every date starts at today; the panel shown is remembered, not its choices. The calendar is our own exact code on whole day numbers (`core/calendar`: the Gregorian calendar carried back, day numbers by Hinnant's era method; `core/datecalculation`); whole numbers are exact, so no fraction or floating point is needed (D-010). Difference: the whole months counted from the earlier day, each month's day brought back to the month's end (31 January plus one month is 28 February), as years and months; the rest as weeks and days; and the whole difference in days ("Same dates" for one day; the parts that are 0 left out; singular and plural; the order of the dates does not matter). Add: years, then months, then days; Subtract: days, then months, then years; after each step a day beyond the month's end becomes its last day; a result before 1 January 1601 or after 31 December 9999 is "Date out of bound". Results only with Calculate (or Enter in a date or number box, which then gives the first result box the keyboard focus); a changed date, number or Add/Subtract empties that mode's result. The number boxes take up to three digits, may be empty (0), and their arrows (and Up, Down) step from 0 to 999 and round. The date boxes show the regional short date, always with a four-digit year, from 1601 to 9999; Up and Down go round in the day and month and stop at the year's ends; the result date is written in the regional long date. Tab order: the mode's parts, Calculate, the calculator, the mode list; only the chosen one of Add and Subtract takes Tab, the arrows choose. Commands: `date.mode.N`, `date.difference_from`, `date.difference_to`, `date.shift_from` (a date "2026-10-30"), `date.add`, `date.subtract`, `date.years`, `date.months`, `date.days` (a text), `date.years.up` and the other arrows, `date.calculate`; `chrono-calc-cli` prints the panel. All 24 differences and 30 Add or subtract results of Windows 7 match. Windows 7 fault not copied: opening the calendar and closing it without a change empties the results (nothing changed, so they stay). Our own, not measured: the calendar's look (Qt's calendar in our colours), the Calculate button's drawing, the arrows beside the number boxes; the number boxes end where their arrows begin (Windows 7 overlaps them by 2 px). (2026-10-30)

- **D-027** The Worksheets (M8), measured on the Windows 7 Calculator (`tests/reference/windows7-worksheets.md`), side panels of D-025's family (`view.mortgage`, `view.vehicle_lease`, `view.fuel_economy_mpg`, `view.fuel_economy_litres`; View > Worksheets has no dot of its own, and while a worksheet shows Basic, Unit conversion and Date calculation have none; the list takes the keyboard focus when one is chosen). Each worksheet has its values in its own order and a sorted list of those it can calculate (`core/worksheets`); the boxes never move: the chosen value has no box and is the result, the others keep their order, so choosing another value relabels the boxes, the old result becomes a box and the chosen value's text the result (`core/worksheetcalculator`, one state per worksheet, kept over view, panel and worksheet changes; only the panel shown is remembered). Formulas on the engine's `Rational` with its own `Pow` and `Log` (D-010), payments at the end of each period: Mortgage i = rate/1200, n = term*12, payment = (price - down) * i / (1 - (1+i)^-n), Term from (1+i)^-n = 1 - loan*i/payment; Vehicle lease i = rate/(100*payments per year), n = period*payments per year, payment = (value - residual*(1+i)^-n) * i / (1 - (1+i)^-n), Lease period from (1+i)^-n = (value*i - payment)/(residual*i - payment); mpg = distance/fuel; L/100 km = fuel/distance*100. "Unable to calculate" for a division by zero, a term, period or payments per year of 0, or a payment that never repays.
